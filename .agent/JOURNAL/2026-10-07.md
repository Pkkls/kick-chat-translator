## Per-channel pause, ported and finished

The bar's pause still wrote the global `enabled` on master. The fix lived on
`feat/nav-monde-isole`, based on 2.10.0, with one quarter of its scenario red.
The URL poll from that branch had already reached master; the pause had not.

Port alone, `nav-monde` on the fixture:

    pause clicked, same channel        traduite NON
    resume clicked, same channel       traduite OUI
    C. next channel after a pause      traduite OUI
    D. return to the paused channel    traduite OUI   <- red

Cause, located: the probe changes the URL and the chat content in one tick. The
observer handles the new row within milliseconds, the poll sees the URL up to
500 ms later, so the row ran through the pipeline with the view of the channel
being left. `ChatObserver` sets `data-kt-id` before the callback, and `reset()`
only clears `seenIds`, so the poll's reset skips the row (`prev === id`). A row
translated in that window stays translated.

What did not work as a plan, before writing it: skipping the row in the callback
when the slug is stale and letting the poll's reset pick it up. The mark makes
that a silent drop. Read before written, so it cost nothing, but it is the
obvious first idea and it is wrong.

Fix: the observer callback compares `extractChannelSlug(location.pathname)` with
`currentSlug` and calls `attachForRoute()` first when they differ. Same probe,
D `traduite NON`, all 7 lines as expected. Reprise, A and B still translate after
D, so D is not a probe that stopped seeing anything.
