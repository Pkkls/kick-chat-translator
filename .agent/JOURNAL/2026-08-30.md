# 2026-08-30

## What this pass built

The working system itself: `.agent/`, a standing prompt with no dated fact in
it, a state file nobody writes by hand, a queue, and this journal. No file under
`src/` changed.

## Why

A handoff written on 2026-08-27 opened a session on 2026-08-29 with four claims
about the repository. All four were wrong: it said the tree was clean (thirteen
modified files), that HEAD was on `196b441` (five commits further on), that the
version was 2.8.0 (2.8.1), and that the offline gates ran in series and
parallelising them was the first untouched opportunity (`run-gates.mjs` had been
pooling one worker per core, with a `--jobs` flag, all along).

The lesson is not that the author was careless. It is that prose about a
repository decays at the speed the repository moves, and that a frame and a
state cannot live in the same file. So `PROMPT.md` is forbidden from containing
a version, a commit, a count or a current open point, and `ETAT.json` is
forbidden from being edited.

Both fixed before the file was used for anything.

## The apparatus does not survive a machine

`git ls-files scratchpad/` returns 0. Every gate, every harness and every audit
is under a directory `.gitignore` excludes at line 18. They exist here and
nowhere else, and a fresh clone of the public repository gets none of them,

## Second pass: the apparatus now survives a machine

Taking the first open item, which was the one that undermined the rest.

**What made it hard, measured before deciding.** Playwright is not a dependency
of this project, and 33 harnesses each carried the same absolute path into one
home directory as its fallback location. There is CI, two jobs on node 20, and
it never runs these gates: adding Playwright as a devDependency would pull
browser binaries into both installs for nothing. And the split that settled what
to track: 422 KB of scripts against 272 MB of screenshots, HTML dumps, bundles
and browser profiles.

**What was done.** A single `scratchpad/harness/playwright.mjs` resolves the
browser from `$UX_KIT`, then from a gitignored `scratchpad/uxkit.path`, then
from the repository's own `node_modules`, and exits 2 when none of the three is
there, printing all three ways to fix it. Exit 2 and not 1, because a machine
without Playwright is a missing prerequisite and not a failed gate, and a runner
that cannot tell those apart reports the first as a product defect. The 33
harnesses import it. `.gitignore` re-includes `*.mjs` and `audit_*.py` under
`scratchpad/` and nothing else, so 40 files and 291 KB enter and every output
stays out, along with the French working prompts.

**Three things went wrong doing it, all mine.** The bulk rewrite missed
`snapshot.mjs`, whose two lines were written on one line. It missed
`measure-popup.mjs`, which had its own home-made resolver, and then turned
`const chromium = await loadChromium();` into `const chromium = chromium;`,
which the gate caught as "Identifier 'chromium' has already been declared". And
the first gate run after the rewrite failed with exit 2 everywhere, correctly:
the private path was gone and nothing had replaced it yet, which is what the
`uxkit.path` file is for.

**Verification.** `node --check` on all 35 harnesses, then 18/18 gates green,
19.5s of wall clock against 114.2s cumulative, factor 5.86. Then typecheck,
lint, 620/620 tests and build. The gates are the verification of a mechanical
rewrite across 33 files; reading the diff would not have caught
`const chromium = chromium;` as fast as running it did.

**Left open on purpose.** 19 harnesses of 35 are still in no runner, and the
live ones still have no entry point. Tracking them was the prerequisite for
fixing that, not the fix.

## Fourth pass: two gates that could not fire, and one that now can

**`latency` had never run.** It reads counters only a metrics build emits, and
`check-strip.ts` fails a release build that keeps them, so an ordinary dist
carries none. It detected that and exited 2 with the reason, which is the right
refusal and also meant every pass skipped it forever. It has its own phase in
`run-live.mjs` now: last, alone because it rewrites dist underneath everything
else, building metrics, measuring, and restoring the ordinary build in a
`finally` so a failed measurement cannot leave counters in a package. First run
in its life: green, 108.3s.

**The node version is no longer something to remember.** The 2.9.x packages went
out built on 22 while `.nvmrc` pins 20 and CI builds on 20; `engines: >=20`
allows both, so nothing anywhere objected and it surfaced only while writing
reviewer notes that had to state a version. `pack.ts` prints the running version
and the full sha256 with every archive and says when it differs from the pin. A
warning rather than a failure, because refusing would have the packer contradict
`engines`.

**And that printing immediately caught something worse.** The sha of the freshly
packed 2.9.2 was not the sha of the published 2.9.2: rebuilding after the
placement fix had overwritten it. Same version number, a different build, which
is precisely how a stale package reaches a store. `state.mjs` compares every
local archive's size against the published release now and says so at every
start; local chromium is 294379 bytes against 294586, a delta of 207. The
condition itself stays open until this branch merges and a 2.9.3 ships, and
nothing in `release/` should be submitted while the warning is up.

## Fifth pass: the flapping was a mute probe, and I had filed it as weather

The queue said "the live gates are not deterministic", with the channel, the
chat volume and the network as the suspects. That framing was mine and it was
wrong in the most useful way: it turned three separate defects into one property
nobody can fix.

`live-kick` was setting `.value = 'fr'` on the bar's language control and
dispatching a `change` event. That control stopped being a `<select>` when the
shared panel replaced it, and `langMenu.ts` documents the replacement in its own
header. On a `<button>`, both lines do nothing. So the target was never changed,
and the translation count that followed was counting whatever the default target
had produced: it came out above zero when `/browse` served a channel in a
language the browser default differed from, and zero when it did not. Weather,
apparently. A probe that cannot perform the action it is testing.

It drives the real control now: click the button, take French from the panel,
and read the control's own label back before counting anything. Zero after a
target that never moved and zero after a broken pipeline are the same number,
and only the label separates them. Three runs: 6, 5 and 2 translations, zero
errors, target FR each time. The verdict is steady and the count follows the
traffic, which is the right way round.

Of the other two flaps, one was a null crash in my own keyboard probe, fixed
earlier today, and one was a single unexplained `kick-dom-recon`. So the
systemic claim rested on one unknown and two of my own bugs. Filing weather is
easier than reading three stack traces, and it costs the next reader the chance
to fix anything.

## Seventh pass: measuring the only thing that could be measured

The analytics could not rank a code change, so the question became what in this
repository can be. The answer is the injected script: `assets/content.js` is
downloaded, parsed and run on every kick.com page whether anyone opens anything
or not, and `inject.css` is inlined into it. It is the only cost the extension
imposes on everyone all the time.

Read out of the published archives rather than out of the handoff, which had a
figure for it that was already stale: 199.5, 199.4, 199.4, then 224.3 at 2.9.0.
Twelve and a half percent in one version, for the drawn flags and the shared
panel, sitting there for three days because nothing looked. That growth is mine.

`audit_poids.py` reports the delta every run and fails past a two percent
margin. Its baseline is a constant in the file rather than a JSON beside it,
because `scratchpad/` only tracks `*.mjs` and `audit_*.py` and a data file there
would be gitignored: the baseline would not survive a machine, which is the
mistake this directory exists to stop repeating. Green now, red against a
baseline twelve percent lower, which is the jump it would have caught.

What was measured and then not acted on: the flag rules are 10.9 KB of the
bundle, 45 rules carrying 7.5 KB of SVG data URIs, 18.7 percent of the CSS.
Injecting them lazily on first list open would save 4.9 percent of the bundle
and a parse cost under a millisecond, at the price of a second stylesheet and a
flash risk. Measuring it was worth it; doing it would have been optimising a
number.
